# AI governance: contracts, safety, and release gate

Status: local Release 2 implementation for evaluation, **not** provider or product acceptance. `REVIEW_EXPLANATION` is the only durable AI task; stateless review Q&A is disabled by default. Both are advisory. Discovery, deterministic review, decisions, and audit export must work with all AI flags off.

## Explanation artifacts and provider boundary

`ai_jobs` and `ai_artifacts` accept only `REVIEW_EXPLANATION` under migration `0006`. Accepted artifacts are immutable; jobs use leases, bounded retries, idempotency, and a labelled deterministic fallback. A collision with a different stored input hash is rejected. The existing key still omits review-manifest and provider-approval identity; changing that requires a versioned key and in-flight-job policy. Replay preserves input provenance, not byte-identical model output.

The v5 worker sends validated reason codes, grant type, risk/evidence status, rule version, three pinned evidence IDs, and an explicit effective-access limitation. Raw policy documents, principal and resource names, coverage details, account posture, secrets, and tokens are excluded. The final payload rejects malformed codes, substituted IDs, and prohibited identifiers. Every provider submission requires the source account, a current approval, and a recheck immediately before the call. Queued v4 jobs are retired before provider execution; privacy rejection or an open transport-failure circuit produces fallback without a provider call. Five recent transport failures in ten minutes open that per-model circuit.

The explanation API and worker require `ENABLE_GENAI=true`, `AI_PROVIDER_DATA_APPROVED=true`, `GOOGLE_API_KEY`, `AI_PSEUDONYM_KEY`, `AI_PROVIDER_REGION=global`, and `AI_PROVIDER_APPROVAL_JSON`. The JSON must contain exactly `approval_version`, `approved_by`, `provider=google_genai_api_key`, `model`, `region=global`, `prompt_sha256`, `input_classes` (`EVIDENCE_REFERENCES`, `RULE_TRIAGE`), `approved_account_ids` (12-digit accounts), `terms_sha256`, `retention_sha256`, and timezone-aware `approved_until`. Hashes are lowercase SHA-256; the prompt hash covers the exact prompt prefix and generation configuration. A model, prompt, region, class, terms, account, or expiry change requires renewed approval. This API-key client has no regional routing; `global` approval cannot satisfy a restricted-region requirement. An operator-entered record enforces configuration but does not prove legal, privacy, or provider-terms approval.

Migration `0015_ai_provider_provenance` adds nullable approval version, region, prompt hash, final provider-input hash, and input classes to accepted artifacts and audit exports. v5 model artifacts require all fields; fallback has none. Old artifacts and old writers remain readable as `legacy_missing`, without fabricated provenance. Deploy migration, readers, then writers, and verify PostgreSQL and old-worker behavior before enablement. A future durable task needs account/review/snapshot/observation/grant/manifests, input and output hashes, task/prompt/schema/model/region/approval/generation, citations, validation, error/fallback, tokens, latency, and an explicit cost method.

## Stateless review Q&A

`ENABLE_REVIEW_QA=false` by default. `POST /reviews/{review_id}/ai/questions` accepts `ATTACHMENT`, `RULE`, `LIMITATIONS`, or `NEXT_EVIDENCE`; unknown or unsupported intents abstain. It sends no provider request, stores no conversation, and cannot decide or remediate. Each turn rechecks OIDC reviewer group, account, campaign pool, current assignment, pending status, and open campaign. Former reviewers, decided reviews, and legacy unpinned reviews cannot start a turn. A stale pinned review can be explained with current eligibility disclosed separately.

Retrieval uses only that review's `ReviewEvidenceManifest`, `SINGLE_SOURCE` manifest, observation, and grant assessment. Current scans cannot replace pinned facts. Each claim has exactly `type`, grant `subject`, `value`, `evidence_id`, and `manifest_sha256`; the validator recomputes the value from the pinned bundle before fixed-template rendering. A citation ID alone does not establish support. Validation failure abstains. The supported claim catalog is:

| Claim | Pinned basis and permitted statement |
| --- | --- |
| `POLICY_ATTACHMENT_OBSERVED` / `GROUP_MEMBERSHIP_OBSERVED` | Exact attachment or group-derived relationship, hash, and observation time; observed path only. |
| `TRUST_STATEMENT_OBSERVED` | Role-trust path and statement index; statement captured for inspection. |
| `WILDCARD_PATTERN_DETECTED` / `CONDITION_PRESENT` | Matching rule reason; syntactic finding, with condition effect unevaluated. |
| `POLICY_DOCUMENT_MISSING` / `SOURCE_SCAN_INCOMPLETE` / `ASSESSMENT_INCOMPLETE` | Exact missing, coverage, or rule status and reasons. |
| `AUTHORIZATION_NOT_EVALUATED` | Pinned grant assessment; no effective-access conclusion. |

The endpoint cannot answer whether equivalent paths remain after revocation, whether a replacement policy is safe, cross-account reachability, operational impact, or business need. Free-text classification/paraphrase or durable conversation requires a new privacy, retention, authorization, and grounding design; no Q&A task can be inserted into the explanation tables by changing Python alone.

## Threats and telemetry

Untrusted inputs include OIDC claims until verified, policy text/metadata, question intent, and provider output. Tests cover cross-account/review substitution, reassignment, fabricated citations, changed hashes, group/trust/Identity Center paths, stale/missing evidence, prompt injection, malformed output, and attempted decision language. API authorization and exact claim validation remain the runtime boundaries; an LLM judge is not an authorization control. Q&A tests also assert no decision, remediation, AI-job, or artifact mutation.

When Q&A is enabled, `AI_TELEMETRY_KEY` must be a deployment secret of at least 32 bytes. Each turn logs request ID, intent, result, latency, and keyed HMAC fingerprints of retrieved/considered/cited/unavailable evidence IDs, without raw IDs or question text. `python -m scripts.summarize_ai_telemetry --input <redacted-jsonl-log>` reports outcome and P50/P95 latency. Provider logs record approval version, payload/template hashes, region, and latency. Protect the key and logs. Deployed rate limits, centralized collection, access control, alarms, total task deadline, per-account request and durable spend budgets, and numeric latency thresholds still require a representative baseline and implementation before provider rollout. `AI_MAX_CALLS_PER_INVOCATION` defaults to 10 (maximum 100); it is not a daily budget. Assign an on-call/retry owner and disable procedure. Disable `ENABLE_GENAI`/`AI_PROVIDER_DATA_APPROVED` or `ENABLE_REVIEW_QA` to stop new traffic; handle queued jobs under an audited policy. A provider failure must not block human review.

No Q&A DELETE endpoint exists because no history is stored. Durable artifact removal, retention, archival, tombstones, and allowable retained hashes require a separate contractual decision. Database immutability does not supply protected archive policy.

## Explanation evaluation and release gate

`scripts/build_ai_eval_candidates.py` creates **unreviewed** candidates: 160 synthetic across eight strata (20 each), 30 structural adversarial probes (five per class), and eight ineligible cases. Twenty-five adversarial cases can be model-evaluated; five account substitutions must fail before submission. Output probes exercise the validator, not a model attack. Human IAM review must improve and freeze the corpus before a provider run. The runner requires `--execute`, reviewed synthetic/adversarial inputs, approved and de-identified historical cases, frozen hashes, current provider approval, and an explicit call ceiling; historical outputs stay outside Git. It calls the worker's `_generate` boundary, not the durable job lifecycle.

Run the offline screen with `python -m scripts.evaluate_ai_explanations --cases <approved-cases.jsonl> --outputs <worker-outputs.jsonl> --grades <independent-grades.jsonl> --run-manifest <run.json> --human-study <study.json> --report <report.json>`. It requires at least 100 eligible synthetic cases, 20 in each critical stratum (`group_path`, `role_trust`, `identity_center`, `explicit_deny`, `condition_notaction`, `wildcard`, `missing_stale`, `unsupported`), 30 adversarial attempts including 25 model cases and five preflight rejections, and 50 approved historical cases. It checks exact run metadata, fixture/input/final-payload hashes, output schema, review-local citations, privacy sentinels, two distinct IAM grades per eligible case, raw and chance-adjusted agreement, 95% groundedness/limitation floors, zero severe/citation/privacy/provenance failures, and an adjudicated reviewer-study record. This screen cannot independently prove grader expertise, provider terms, or that a self-reported study occurred.

Before release, run the exact deployed worker/model, not only the `_generate` helper; verify duplicate delivery, expired lease, timeout, invalid output, unavailable evidence, disabled provider, immutable single acceptance, and fallback. Record latency, queue age, tokens, fallback, errors, spend, and cost per useful review. Two independent IAM reviewers grade factual support, limitations, and improper advice; resolve disagreements. Conduct a powered, counterbalanced reviewer study against the deterministic UI on realistic bundles. Require zero unauthorized/cross-account Q&A responses, correct abstention, no mutation, measured latency and gateway limits, and improved **correct, defensible** reviews. Local fake-provider and structural tests establish implementation behavior only. No approved historical corpus, real-provider run, independent grading, reviewer study, or pilot has been recorded.

Progression: local tests → hosted CI → isolated integration → approved provider evaluation → managed OIDC/AWS staging → controlled reviewer pilot → release decision. Capture exact commit/configuration, owner, results, limitations, and rollback at each gate. Keep broader brief, campaign insight, provider-backed Q&A, and AI-directed remediation disabled pending separate contracts and evaluation.
